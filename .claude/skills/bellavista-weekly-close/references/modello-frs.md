## Как считаются фонды

Выручка недели (`ricavi`) делится на два потока.

**Прямые фонды — доли от выручки, в сумме 50%:**

| Фонд | Доля от ricavi |
|---|---|
| Fondo Agenti | 30% |
| Fondo Partner | 5% |
| Fondo Dirigenza | 5% |
| Fondo Marketing & IT | 10% |

**Маржа** — ровно 50% выручки (`margine = ricavi × 0,5`). Коэффициент зашит
в код приложения и не настраивается через интерфейс.

**Фонды маржи — доли от маржи, в сумме 100%:**

| Фонд | Доля от margine |
|---|---|
| Fondo IVA + Imposte | 35% |
| Fondo Retribuzioni + Tasse | 24% |
| Fondo Dividendi | 15% |
| Fondo Emolumento CEO | 3,969466% |
| Fondo Sviluppo | 3,969466% |
| Fondo Rimborso Investimenti | 3,969466% |
| Fondo Spese Operative | 4,326718% |
| Fondo Affitti | 3,175573% |
| Fondo Obiettivi HR | 2,619847% |
| Fondo Riserve | 2,381679% |
| Fondo Formazione | 1,587786% |

Дробные проценты — не опечатка: это доли, пересчитанные из фиксированных сумм
модели, поэтому в них так много знаков. Округлять их нельзя, иначе перестанет
сходиться контрольная сумма.

**Контроль:** `ricavi − сумма прямых фондов − сумма фондов маржи = 0`.
В приложении это колонка `Check`, она подсвечивается красным при расхождении.
Ненулевой check означает ровно одно: проценты во вкладке «Parametri FRS»
изменили так, что они больше не дают 100%.

Скрипт `frs.py` берёт проценты из выгруженного JSON (поле `params`), если он
передан через `--stato`, и только при его отсутствии использует значения
по умолчанию. Так расчёт остаётся верным даже после изменения модели.

## Календарь недель FRS

Год делится на 52 недели. **Неделя 1 начинается в первый четверг января**,
каждая следующая — через 7 дней. Недели идут с четверга по среду.

- 2025: неделя 1 — 02.01.2025 … 08.01.2025
- 2026: неделя 1 — 01.01.2026 … 07.01.2026

Неделя движения определяется **датой проводки по банку** (`Data contabile`),
а не датой счёта. Это регулярный источник вопросов «почему сумма не в той
неделе»: счёт от 2 февраля, оплаченный 6-го, относится к неделе платежа.

Проверить: `python3 scripts/frs.py weeks --anno 2026 --data 2026-02-09`.

## Категории движений

Категории живут в самом приложении (вкладка «Categorie Spese») и делятся
по области применения: `entrambi` (PO и банк), `po`, `banca`.

**Фонды FRS:** Fondo Agenti, Fondo Partner, Fondo Dirigenza,
Fondo Marketing & IT, Fondo IVA+Imposte, Fondo Retribuzioni, Fondo Dividendi,
Fondo CEO, Fondo Sviluppo, Fondo Riserve, Fondo Rimborso, Fondo Formazione,
Fondo Affitti, Fondo SO.

**Сделки:** Fattura Cliente, Fattura Fornitore (только PO), Storno / Rettifica,
Saldo Commerciale, Onorario Notaio (PO), Onorario Professionista (PO),
Investimento Immobiliare, Rimborso Cliente (только банк), Mediazione Immobiliare.

**Операционные расходы:** Commissioni (банк), Finanziamento IC (банк),
Stipendi (банк), Tasse (банк), Software, Marketing, Spese Ufficio,
Formazione Esterna, Consulenze, Altro.

Категории, которых нет в этом списке, придумывать не надо — сначала их заводят
в приложении, иначе движение не свяжется с существующей аналитикой.

## Структура JSON приложения

Выгрузка (Dashboard → «Backup completo JSON») выглядит так:

```json
{
  "schema": "bellavista-financial",
  "schemaVersion": 1,
  "exportedAt": "2026-02-12T10:00:00.000Z",
  "data": {
    "weeks":  [{"date": "2026-02-05", "amount": 152500}],
    "po":     [{"date": "…", "supplier": "…", "desc": "…", "amount": 3150,
                "cat": "…", "requester": "AM - Angelina", "approver": "…",
                "status": "attesa|approvato|pagato|rifiutato|annullato", "note": "…"}],
    "bank":   [{"date": "2026-02-09", "desc": "…", "in": 100000, "out": 0,
                "cat": "Fattura Cliente", "rec": "N|S|P"}],
    "params": {"agenti": 0.30, "…": 0.0},
    "bankBalances": {"conto": 0, "libro": 0},
    "categorie": [{"name": "…", "type": "entrambi|po|banca"}],
    "deltaEdits": {"6": {"amt26": 152500, "desc26": "…"}}
  }
}
```

Импорт принимает как обёртку целиком, так и голый объект `data`. Обязательны
массивы `weeks`, `po`, `bank` — без них приложение отклонит файл. Импорт
**заменяет** все данные, поэтому перед ним всегда делается бэкап.

Поле `rec` в движениях банка — признак сверки: `N` не сверено, `S` сверено,
`P` частично.

## Дельта 2025/2026

Вкладка «Delta 2025/2026» сравнивает расходы 2025 года с поступлениями 2026-го
по неделям. Суммы 2025 года зашиты в код (`DELTA_BASE`) и не редактируются;
данные 2026 года правятся в интерфейсе и хранятся в `deltaEdits` по номеру
недели. Прогрессивная дельта — накопительный итог `amt26 − amt25` с начала года.

Если закрытие недели меняет поступления 2026 года, значение в этой вкладке
нужно обновить отдельно — оно не подтягивается из движений банка автоматически.
